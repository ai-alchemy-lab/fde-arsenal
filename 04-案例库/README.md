# 案例库

这里放的是哈佛商学院式的教学案例，用来训练 FDE 的现场判断力。每个案例都在关键抉择处停下来，逼你在信息不全的情况下先做决定，再和当事人的实际走法对照。判断力练不出来的原因通常只有一个，读者太快看到了答案。

## 用法

1. 课前完整读一遍案例的「背景」和「冲突升级」，别往下翻。
2. 停在「决策点」。把自己放进当事人的位置，从给出的选项里选一个，写下理由，最好也写下你预计会付出的代价。口头想一想不算数，写下来才暴露得了自己的思维。
3. 再读「实际走法与结果」和「复盘」，对照自己的选择。选对了，检查理由是否和当事人一致，理由错着选对不算对。选错了，找出自己漏掉的那个信号。
4. 小组用法更好。各自作答后互相攻击对方的选择，再开答案。

「复盘」里的原则都写成「下次遇到什么信号就该做什么」的格式，方便带进你自己的项目。

九个案例里有意做了三组配对。Airbus 与 POC 陷阱是「任务定义」的正反面，恒岳重工与专业边界是同一个检修场景的正反面，Distyl 与冠军离职是「把价值钉进组织」的正反面。建议成对读。

中国企业先读安克和澜码这一对，一内一外，正好是路径之争。安克是公司自己的人把 AI 推进业务，澜码是最懂行的外部服务商用最对的方法去挖客户的专家知识，两边的方法几乎是同一套，处境完全不同。读完这一对再回头看自己公司的问题，通常不用别人下结论。要提醒一句，澜码那篇写的是外部交付在中国面临的结构性难处，一家公司的结局定不了一个模式的生死，别读成判决书。

Kavak 单独成一类，它不解决「怎么把项目做成」，它解决「这批人到底该为谁的目标干活」。前八个案例都在谈交付，Kavak 谈的是交付之后往哪儿走，适合放在最后读。

## 关于真实性

- 所有案例基于公开信息，每篇文末有「来源与可信度」一节，写明每个关键数字的出处和可信程度。
- Airbus、Distyl、安克、澜码、Kavak 五案的人物、时间、数字均可回溯到公开来源，各篇文末列出了逐条出处与保留意见。
- 安克一案的「冲突升级」是依据公开机制反推的处境重构，不是被报道过的内部事件，文首有标注。澜码一案的成本结构分析是从公开信息推出的判断，不是财务数据，且明确不构成对该类商业模式整体可行性的结论。
- 日活 12 到 1800（恒岳重工那个故事的网络流传版）与专业边界两案，源自中文互联网流传的叙述与公众号辩论，细节未经独立核实，文首均有显著标注。
- POC 陷阱与冠军离职为教学用复合案例，情节综合自公开调研中的典型模式，公司与人物非实指，引用的统计数字（MIT NANDA、Gartner、RAND）真实可查。

## 投稿

欢迎社区按同样格式投稿真实案例，标准如下。

1. 结构固定。背景、冲突升级、决策点、实际走法与结果、复盘、来源与可信度，六节缺一不可。
2. 决策点必须真的停在两难处。给出当事人当时面前的 2 到 3 个选项，每个选项都要有真实的代价，并向读者提问。事后看来毫无悬念的选择不构成案例。
3. 篇幅 1200 到 2000 字。数字要精确，省了多少钱、花了几周、日活多少，写得出数字的地方不要用「大幅」「显著」。
4. 必须脱敏。隐去可识别的公司名、人名、具体金额中涉密的部分，但要在来源节里说明脱敏范围，以及作者与案例的关系（亲历、二手、公开材料整理）。
5. 来源诚实。分清三档，可公开查证、行业流传未核实、复合合成，在文首或文末标清楚。宁可标低一档，不可标高。
6. 复盘写成「下次遇到 X 信号就该 Y」，不收「要以客户为中心」这类大道理。
7. 提交方式，向本仓库发 Pull Request，文件名沿用「胜-」「败-」前缀。

失败案例尤其欢迎。这个库里最值钱的是败例，愿意把自己的败例写出来的人，是这个社区最想要的人。
