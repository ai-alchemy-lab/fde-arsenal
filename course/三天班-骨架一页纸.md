# 《第一仗》三天开局班 · 一页骨架

> 后面三份手册加起来四万多字，是给教练备课用的。**这一页是给所有人用的**：打印出来，贴在教室墙上，也贴在你自己工位上。
> 忘了细节不要紧，忘了这一页就会乱。

---

## 怎么用这一页

**开班前**：照着「五步总表」排你的三天，照着「十一张表用在哪一步」备物料。

**上课中**：每一步开始念一遍**进场卡**，结束核一遍**出场卡**。出场卡没勾满，不许进下一步。

**卡住时**：翻到最后那张「卡住了查哪里」，按现场症状找对应的一节。

## 全景：三天走五步

```
   开工前 · 课前 21 天
   └─ 要赢的行为：拍板人书面确认到场 ＋ 数据切片实际到手
         ▼
   ① 给权 · Day1 上午 · 负责人主场
   └─ 要赢的行为：负责人当着全班，念出止损条款
         ▼
   ② 选题 · Day1 下午
   └─ 要赢的行为：痛的那个人在电话里答应，每周陪你两小时
         ▼
   ③ 挖真问题 · Day2 上午 ★ 全课最重
   └─ 要赢的行为：一个不归你管的人，用他自己的话复述你的问题
         ▼
   ④ 定标准 · Day2 下午 ★ 与传统实施工程师的分水岭
   └─ 要赢的行为：业务方在及格线那一行，签下自己的名字
         ▼
   ⑤ 排兵签字 · Day3
   └─ 要赢的行为：老板在一页立项书上签字
         ▼
   30 天实战 · 课后
   └─ 要赢的行为：老板拍板 —— 扩大 / 调整 / 停止
```

**这张图只有一件事要你记住**：下面那一行——**六个动作，全部是别人做出来的，没有一个是你自己交的东西。**

# 逐步展开：十张卡

每一步进场念一张，出场核一张。

---

## 开工前 · 进场卡

**这一步值什么**　交付的成败一半在开场前。Palantir 的客户集训营用的是同一份清单。

**要赢的行为**　拍板人书面确认 Day1 上午和 Day3 下午到场；数据切片实际躺在你硬盘上。

**分四小步**

1. 企业方和 FDE 各交一份报名问卷（T-21）
2. 启动数据切片的脱敏与合规审批（T-14，**最容易拖的一步，越早越好**）
3. FDE 跟一天班，交一页现场笔记（T-7）
4. 教练打 30 分钟一对一诊断电话，负责人和 FDE 分开打（T-7）

**填哪几张表**　企业方报名问卷、FDE 候选人问卷、客户准备协议、跟班笔记

**大约用时**　三周日历时间，实际投入每方约 3 小时

## 开工前 · 出场卡

**手里必须有这些，才开课**

- [ ] 一个具体的人名，以及选他的三条事实（不是评价）
- [ ] 200–500 条脱敏真实记录，**没有被清洗过**
- [ ] 拍板人两段到场的书面确认
- [ ] FDE 的跟班笔记，第四格「我以为 vs 实际是」不一样
- [ ] 教练诊断结论：绿 / 黄 / 红

**没做到就别往下走的那一条**　数据切片没实际到手。企业方说"数据没问题，你先开始"——**这句话是最大的危险信号。**

**卡住了查**　学员包第二节（时间线）、第五节（数据切片规格与给数据部门的话术）

---

## ① 给权 · 进场卡

**这一步值什么**　没有对前线的极端授权，你招来的只是贵价外包。对内部培养同样成立——**没有授权的内部 FDE，只是一个多了个新头衔的加班的人。**

**要赢的行为**　负责人当着七家同行的面，把止损条款念出声。

**分五小步**

1. 三个死掉的系统，决策点冻结法研讨（POC 陷阱 / 冠军离职 / 日活 12）
2. 立论：中国为什么只能内部培养
3. 九站全景 + 三条铁律 + 选造用算，发贴墙版
4. 负责人执笔写授权书五条，FDE 只许提问不许代笔
5. 导日历，逐条问"这个会他不去会出什么事"，答不出事的全砍

**填哪几张表**　午餐三问卡 → 授权书（五条）→ 日历两列表

**大约用时**　Day1 09:00–14:45（含午餐）

## ① 给权 · 出场卡

**这一步交付了什么**

- [ ] 授权书五条全部有具体内容，**没有一条写"视情况而定"**
- [ ] "不可以碰的"那一栏至少两条（写不出来的，说明还没想过专业边界）
- [ ] 建议退出的会议 ≥ 3 个
- [ ] 与原岗位老板的交换条件，写了具体内容
- [ ] 止损条款已当众念出，且念的时候没有补"当然我还是希望能成"

**判断点**　本步 2 格（时间保护几成、交换条件）

**没做到就别往下走的那一条**　时间保护给不到位。**一个每天还要开六个会的人做不了 FDE，这一条没有折中方案。**

**卡住了查**　逐时手册「13:00–14:30 工作坊 1」及其卡点表

---

## ② 选题 · 进场卡

**这一步值什么**　候选不到几十个就直接立项，本质是在信息最少的时候押注。安克先用 Hackathon 铺出 50 多个候选再收敛；毕昇跟上百家企业聊完的建议是先拿两三百个场景做尝试——**一家做内部培养的上市公司，和一家靠卖服务赚钱的厂商，给出了同一个动作。**

**要赢的行为**　那个最痛的人，在电话里答应接下来四周每周陪你两小时。

**分五小步**

1. agent 拉一遍 + 你自己挖一遍，凑够 **12 张海选卡**
2. 伪需求过滤器四问，一问不过就出局
3. 2×2 排序，**只留右上角一张**
4. 一页立项书 v1，教练第一轮批改（只问不答，六个问题）
5. 当晚打那通电话，记下他答应时的原话

**填哪几张表**　场景海选卡 ×12 → 伪需求过滤器 → 2×2 → 一页立项书

**大约用时**　Day1 15:00–18:15 + 当晚

## ② 选题 · 出场卡

**这一步交付了什么**

- [ ] 海选卡 ≥ 12 张，"谁在痛"全部写到人名，没有一张写"公司层面"
- [ ] 至少 3 张不是来自老板给的那份清单
- [ ] 2×2 右上角只有一张卡
- [ ] 立项书六格全填、指标唯一、"不做" ≥ 3 条、零个行话
- [ ] 电话打了（不是微信），有一句原话 + 一句语气判断

**判断点**　本步 4 格

**没做到就别往下走的那一条**　顶不住左上角的诱惑。老板最兴奋的场景常在那儿——价值高、数据拿不到。话术要当众练一遍：**"这一仗我们记在第二仗清单最上面。先用右上角这仗证明方法，30 天后我们带着战绩来打它。"**

**电话被拒绝了怎么办**　不算失败，算收获——你拿到了一个真实信号：这个场景的痛人不痛。第 1 天发现比第 90 天发现便宜太多。当众表扬，中午前重跑海选。

**卡住了查**　逐时手册「工作坊 2 / 3 / 4」

## ③ 挖真问题 · 进场卡

**这一步值什么**　全课最重的一步。那套设备检修知识库日活 12，接手的人做的第一件事不是调模型，是跟车，跟了十天。之后他改的几件事**全部和模型能力无关**，日活到 1800，排障从 47 分钟到 22 分钟。

**要赢的行为**　一个不归你管的人，用他自己的话把你的问题描述复述一遍，然后说"对，就是这个"。

**分五小步**

1. agent 生成 25 问提纲，**你亲手删到 7 问**
2. 三轮难缠角色访谈演练，每轮 12 分钟访谈 + 8 分钟公开拆解
3. 转写抽三份清单（带数字的 / 带"但是如果"的 / 提到人名的）+ 跨场次矛盾检测
4. 写 150 字问题描述：谁、哪个环节、什么代价、一个数字、一句原话
5. **跨企业复述测试**——交给另一家的人，读完把纸倒扣，让他复述

**填哪几张表**　访谈提纲库 → 利益相关者地图（五种人写出名字）→ 问题描述 150 字

**大约用时**　Day2 08:45–13:40

## ③ 挖真问题 · 出场卡

**这一步交付了什么**

- [ ] 提纲从 25 删到 ≤ 8，且删的理由说得出来
- [ ] 三轮演练全部完成，每轮有拆解记录
- [ ] 转写落进工作台，三份清单已生成
- [ ] 从矛盾清单挑出 1 条，写了为什么是它
- [ ] 通过至少一次跨企业复述测试

**判断点**　本步 6 格

**没做到就别往下走的那一条**　访谈时在现场记笔记。**注意力全部留给追问，记录交给 agent。**

**这一步最容易错的判断**

- 哪句是真话，哪句是客套——「你先做一个出来我们看看」翻译过来是「我不打算投入」
- 数据看门人：**不要跟他谈数据，跟他谈安全**
- 专业边界：**凡是有安全规程的领域，判断规则不得由你来定**。这条没有例外

**卡住了查**　逐时手册「工作坊 5 / 6」、讲师手册第四节六个角色剧本

## ④ 定标准 · 进场卡

**这一步值什么**　这一站是 AI 时代的 FDE 区别于传统实施工程师的硬技能，也是市面上材料集体跳过的一站——中文世界流传最广的那本 FDE 手册，评估体系那一节九百字，零样例、零维度、零 judge 提示词、零阈值。**别人一笔带过的地方，我们花一整个下午，而且当场跑出一致率的数字。**

**要赢的行为**　业务方本人标完样本，并在及格线那一行签下自己的名字。

**分六小步**

1. 逼出"什么算好"：业务方原话一句 + **三个反例**（反例比正面定义值钱）
2. 分层抽样：日常主流 60% / 边角 20% / 历史出过事的 10% / 故意刁难 10%，**50 条起步**
3. 两个人独立标同样 20 条，算第一次一致率，**公示在墙上**
4. 摊开分歧逐条问"你俩为什么判得不一样"，把统一口径**写下来**，重标，第二次一致率 ≥ 85%
5. 写 judge 提示词（把口径手册翻译一遍），跑批，比对一致率
6. 阈值决策格四档，**每格填上谁承担后果的人名**

**填哪几张表**　Eval 设计卡第一块 → 第二块 → 第三块 → 第四块

**大约用时**　Day2 13:40–18:00

## ④ 定标准 · 出场卡

**这一步交付了什么**

- [ ] "他看到输出之后要做的动作"是个动词，不是"参考"
- [ ] 漏报 / 误报选了一个，且有理由（答"都重要"的要追问到他选为止）
- [ ] 三个反例是业务方给的，不是你编的
- [ ] 评估集 ≥ 50 条，四层占比对得上
- [ ] 墙上有**两个**一致率数字，第二次 ≥ 85%
- [ ] 及格线那一行有业务方签名
- [ ] judge 提示词六个标准填的是具体内容，不是"准确""合理"
- [ ] 阈值四格每格有具体人名

**判断点**　本步 6 格

**没做到就别往下走的那一条**　一致率到不了 85%。**不要放水**——这说明第一块的"什么算好"当初没定清楚，回去重填。这是正确结果，不是失败。

**两条最容易搞反的**

- judge 和人不一致时，**改的是 judge，不是模型**。拿一个没校准的裁判去调模型，越调越偏
- **拒答是一等公民**。宁可拒答也不要瞎猜——老师傅被坑一次，这个系统在他那里就永久死亡

**卡住了查**　逐时手册「工作坊 7 / 8 / 9」、模板库 Eval 设计卡

## ⑤ 排兵签字 · 进场卡

**这一步值什么**　造、用、算三站要真实时间，三天里只能排练。这一步的产物不是系统，是**一张排到日的 30 天日历，和一个签了字的赌注**。

**要赢的行为**　老板当着全班，在一页立项书上签字，或者说清楚为什么不签。

**分七小步**

1. 范围砍三刀，四问自查，同组当谋杀委员会撕
2. 采纳三件套自查（入口 / 语言 / 带头人），抵抗诊断三选一演练
3. agent 军团编制表：四个岗位的输入输出 + **每岗"我必须自己赢的那一格"**
4. ROI 测算表只填 W1 预估列，实测列留白给 30 天
5. 立项书 v3 定稿，教练第三轮批改（后六个问题）
6. 结业答辩三段式：3 分钟陈述（**不许放 PPT**）+ 5 分钟现场跑（**不许放录屏**）+ 4 分钟质询（**只问判断点**）
7. 当场签字，或当场做不签的诊断

**填哪几张表**　MVD 范围切割卡 → 采纳设计检查表 → agent 编制表 → ROI 测算表 → 管理层汇报一页纸（只搭骨架）→ 一页立项书 v3

**大约用时**　Day3 全天

## ⑤ 排兵签字 · 出场卡

**这一步交付了什么**

- [ ] 砍了三刀，说得出数据从哪进、**结果写回哪里**（答不上来的是只读系统，不产生任何采纳）
- [ ] 入口是已有动线，不是新门户
- [ ] 老师傅版本的话术是问来的，不是编的
- [ ] 四个 agent 岗位的"自己赢那一格"是自己写的，不是抄参考答案
- [ ] ROI 表口径列全填，心里打鼓的数字自己降级了
- [ ] 立项书 v3 六格全满、指标唯一、基线已测或写明怎么测
- [ ] **签字栏有笔迹，日期是第三天**
- [ ] 30 天作战日历排到日，D4 和 D9 两天在墙上圈出来了

**判断点**　本步 6 格。三天累计 24 格，**勾满 18 格算过**

**不签字怎么办**　不签是被允许的，而且不丢人。**勉强签的项目会在第 15 天悄悄死掉，当场不签能让我们立刻找到真正的卡点。** 按顺序查三样：拍板人 → 数据授权 → 时间保护，绝大多数原因都在这三样里。诊断结论写进结课报告，进 30 天陪跑第一次一对一。

**卡住了查**　逐时手册「工作坊 10 到 14」「结业答辩」「当场拍板签字」

# 十一张表，用在哪一步

不要一次全用。**第一仗真正必需的只有四件**：客户准备协议、一页立项书、访谈提纲库、Eval 设计卡。其余七件按需取。

| 表 | 用在第几步 | 一句话干什么 | 权威祖先 |
|---|---|---|---|
| 客户准备协议 | 开工前 | 让企业方到位三样东西，缺一不开工 | Palantir AIP Bootcamp；Lawrence 数据就绪度分级；Bain RAPID |
| 场景海选与伪需求过滤器 | ② | 从一堆"要搞 AI"里筛出值得打的一仗 | 麦肯锡《Rewired》；Amazon Working Backwards；Hubbard 澄清链 |
| 一页立项书 | ②（v1）→ ⑤（v3） | 六格纸，老板签字才算过关 | 丰田 A3；Amazon PR/FAQ；Minto SCQA |
| 访谈提纲库 | ③ | 问出事实，不是恭维 | The Mom Test；Contextual Design；丰田现地现物 |
| 任务拆解卡 | ③→⑤ | 把流程切成"AI 预测"和"人判断"两半 | AI Canvas（HBR 2018）；《Prediction Machines》 |
| **Eval 设计卡** | ④ | 和业务方定义什么算好，再动手 | Machine Learning Canvas（CC BY-SA 4.0） |
| MVD 范围切割卡 | ⑤ | 缩小范围不缩小价值的切法 | Cockburn 行走骨架；Basecamp《Shape Up》 |
| 采纳设计检查表 | ⑤ | 入口／语言／带头人三件套自查 | Prosci ADKAR；Rogers 创新扩散；Google PAIR |
| ROI 测算表 | ⑤ 填预估 → 30 天填实测 | 按成果价值算账，同一张表用两次 | Forrester TEI；Hubbard《How to Measure Anything》 |
| 管理层汇报一页纸 | ⑤ 搭骨架 → 30 天用 | 用决策语言汇报：扩大／调整／停止 | 医疗 SBAR；美军 BLUF；Minto 金字塔 |
| 交付病历 | 30 天结案 | 每单交付的标准归档格式 | Weed 的 SOAP；美军 AAR 四问；Google SRE 无责复盘 |

**为什么每张表都标祖先**：你回去要说服你老板的时候，"这是丰田 A3 改的""Palantir 的客户集训营用的是同一份清单"，比"这是我上课学的"好用一百倍。**借势的方式，就是把出处摆出来。**

# 卡住了查哪里

按现场症状找，不按章节找。

| 你遇到的情况 | 先做什么 | 详细查 |
|---|---|---|
| 老板说"你先做个 demo 我们看看" | 这是「我不打算投入」。把客套逼成一个日程：下周三上午两小时，您陪还是指个人 | 讲师手册 · 角色 3 |
| 数据部门一直挡 | 别谈数据，谈安全。摆角色权限、行级策略、审计日志 | 逐时手册 · Day2 上午；讲师手册 · 角色 1 |
| 老师傅全程"挺好的"，不给真话 | 别问"您一般怎么修"，问"您上一次遇到这个报警是什么时候" | 讲师手册 · 角色 2 |
| 有人专业地反对，句句在理 | 先判断是不是第三种抵抗（动了奶酪）。**别去论证准确率够了，她要的不是这个答案** | 讲师手册 · 角色 4 |
| 领导要 100% 准确率 | 不承诺准确率，切到"错了会怎样"：哪类错您半夜会接到电话？低到多少该拒答？ | 讲师手册 · 角色 5 |
| 老板给的题太大 | 拆成第一仗 + 第二仗清单，**当着他的面把第二仗清单记下来** | 讲师手册 · 角色 6 |
| 用户要加需求 | 三步：当面记进第二仗清单 → 说那句话术 → 零例外 | 逐时手册 · 工作坊 10 |
| 会开了好几场，没人说"我批" | 拍板人不明。当面问一个人"这件事你能拍板吗"，答不上就请他指出能拍板的人，回第 ② 步重写立项书 | 附录 A · 卡住时先查这三样 |
| 演示很好，一接真数据就散架 | 数据授权没到位。回开工前那一步，不要跳过 | 学员包 · 第五节 |
| 系统上线了，日活 12 | 不是技术失败，是采纳设计失败。查三件套：入口／语言／带头人 | 逐时手册 · Day3 上午 |
| 一致率死活到不了 85% | **这就是正确结果。** 回 Eval 设计卡第一块重填 | 讲师手册 · 事故 6 |
| 第 30 天结论是"这个场景不值得做" | 这算赢。写高质量复盘，**烂尾才是唯一的失败** | 总纲 · 第八节 |

# 如果你只记住一件事

**六个过关标准，全部是别人做出来的动作。**

拍板人确认到场、负责人念出止损条款、痛的人答应每周两小时、业务方在及格线上签名、老板在立项书上签字、三十天后老板拍板——**没有一个是你自己交的东西。**

你写的 PPT、你做的总结、你的感受，一律不算证据。

这条是整套方法的脊椎。删掉它，剩下的只是一张排期表。
