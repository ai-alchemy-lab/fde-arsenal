# 中国 FDE 手册

> 库名待定稿，见根目录命名讨论。本 README 为 v2 重写版。

我是任鑫，公众号「AI 炼金术」的作者。过去几年我干两件事，一边帮企业做 AI 转型的咨询，一边投 AI 相关的公司。两件事都逼着我泡在同一个现场里，看一家又一家公司买了 AI、开了动员会、立了项，然后卡住。

这个库是我把现场里攒下来的方法、模板、案例，整理成的一份手册。后面还有我在研究过程中，按我自己的品味挑进来的全球最值得读的材料。它不是一个资料收集站。市面上不缺资料，缺的是有人告诉你哪些是真的、哪些能用、按什么顺序用。这份判断我来出，对错也算我的。

## 先把我的判断放在最前面

**中国企业的 AI 转型，最后都会卡在同一个地方，缺人进到业务里去改流程**。现在人人都知道要用 AI，但 AI 离传统行业的真实业务很远，中间这个 gap 得有人去填。不是买工具能填的，是要有很多人钻进去，把内部业务流程一块一块地改造掉。

美国的答案叫 FDE，Forward Deployed Engineer，派工程师驻场到客户现场去干。Palantir 靠这个模式做到了 80% 以上的毛利，OpenAI 和 Anthropic 都在扩这样的团队。

但这条路在中国很难走。中国的外包和咨询行业一直没有真正发展起来，企业也不信任外人。所以外部 FDE 生态在中国，实际上就是在做外包，做得非常辛苦。2025 年有个让人唏嘘的注脚，澜码科技，一家方法讲得相当对的外部 AI 交付公司，在保险行业沉淀了 10 万条专家知识，结局是欠薪超 800 万、裁员 66%。一家公司的结局当然定不了一个模式的生死，但它至少说明，在中国做外部交付、想收 Context 沉淀的钱，比想象中难得多。

**中国真正可行的路径，是内部培养 FDE**。道理其实很直白，让懂业务的人去懂 AI，比让外面的人来学你的业务快得多。而且 FDE 是个新事，没有谁天生知道该怎么干，外面的专家反而不见得比你内部的人强多少。你的业务是积累了很多年的东西，AI 是大家都刚上手的东西，这道算术题不难算。

这不只是我的判断。毕昇（BISHENG）跟上百家企业聊完之后自己写下来的结论是，「通过实践培养组织内的人才可能是最可靠的方法」，这话出自一家本该卖平台给你的厂商。安克创新已经把样子跑出来了，AI 代码采纳率从 2023 年的 30% 干到 2025 年的 50% 以上，三年连续、口径一致，靠的不是买了什么工具，是一套内部机制，后面的案例章节会拆开讲。

**你的下一个 FDE，就坐在你的工位上**。

## 这个库教什么，三个核心判断

1. **问题弄清楚了，剩下的 AI 都能搞定**。AI 能力每三个月上一个台阶，写代码、做方案、出报告都在变成便宜的事。真正稀缺的是搞清楚三样东西，真实的问题、真实的 Context、真实的 Eval。所以这份手册的重心压在别人一笔带过的地方，怎么找到值得解的问题。
2. **Agentic FDE，一个人带一支 AI 军团进现场**。调研、分析、写代码、做报告，全部让 agent 干；人只做三件事，判断、信任、拍板。过去要一个团队驻场干的活，现在一个懂业务的人加一套 AI 工作流就能干。这也是为什么内部培养忽然变得可行了，门槛塌了。
3. **FDE 不是降本增效的人，是开疆拓土的人**。改内部流程只是练手。当一家公司真有了一批 FDE，他们的优化函数应该放到客户那边去，客户的 LTV、满意度、新市场。到那一步，这批人就是你开疆拓土的部队，不是省钱的部队。

## 这份手册的来路

FDE 的源头是 Palantir，这段历史和它背后的方法我自己从头梳理了一遍，一手材料的深度导读都在 [01-原典](01-原典/)，书稿里也会有我自己写的版本。这份手册的主战场不在讲历史，在两件市面上没人写透的事，企业怎么长出自己的 FDE，长出来之后每一步具体怎么干。
