# 实践墙

> 这一层不是我写的，是大家填的。

## 这一层和其他目录的关系

军火库分两层。

**骨架层**（`book/`、`02-方法论/`、`03-模板库/`、`04-案例库/`）是我的判断。九站怎么排、每站要赢什么、模板长什么样、哪些案例值得当教材，这些是我出的，对错也算我的。**这一层不接受外部改动**。

**实践墙**（就是这一层）是所有人的。你在某一站上真的干过，有一手的做法、失败、数字、话术、行业变体，挂到对应的挂载点下面。骨架不动，肉越填越厚。

正文里相关小节的末尾会有一行指针指到这里，读者走到哪一站，就能看到那一站所有人的补充——包括互相矛盾的。矛盾不用消除，标出来就行，读者需要看到同一件事在不同行业里的不同长法。

## 收什么，不收什么

**收**：真做过的事，带分母的数字，失败，被拒绝的原话，行业特有的例外，你把模板改了哪一处以及为什么。

**不收**：没有分母的百分比；产品名出现在解法位置（「用 X 平台就能」）；纯方法论综述；没有任何一线细节的成功故事。

判断标准和这本书对自己的标准是同一条：**过关看的是别人的行为，不是你的产出**。你写「客户很满意」不算，写「上线第三周有 11 个人连着五天自己打开了它，其中 3 个原来是反对的」算。

**关于产品名。**你可以署名，可以写清楚是贵司做的，可以在文末留一行链接。但正文里方法要写成任何人都能抄的形态。理由很简单：读者信的是可复现的东西，一段只有买了你产品才能执行的方法，对他没有价值，对你也没有说服力。

## 怎么提

1. Fork 这个仓库
2. 在对应挂载点目录下新建一个 md 文件，文件名格式 `贡献方-一句话主题.md`
3. 按 [贡献规格](../CONTRIBUTING.md) 填好 frontmatter 和正文骨架
4. 提 PR，标题写 `[实践墙] S4 · 毕昇 · 保险场景的例外清单`

我会审。审的是内容不是格式——格式请让你的 AI 按 [贡献规格](../CONTRIBUTING.md) 处理好，那份文档就是写给它读的。

## 署名

每条贡献的 frontmatter 里写贡献方，页面顶部会显示。仓库根目录会有一份贡献者名单，按贡献条数排。
