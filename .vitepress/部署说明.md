# 文档站部署说明

这份说明写给不写代码的人。整个文档站的原理只有一句话：仓库里的 markdown 文件，被一个叫 VitePress 的工具批量转成网页，然后放到一个能被浏览器访问的地方。

内容文件一个都没动。加进来的只有配置文件，都在 `.vitepress/` 这个文件夹和仓库根目录的几个小文件里。

---

## 一、想改站名？改两行

打开 `.vitepress/config.mts`，最上面有这两行：

```ts
const SITE_NAME = '中国 FDE 手册'
const SITE_TAGLINE = '任鑫的企业内部 FDE 培养手册'
```

把引号里的字改掉就行。改完，浏览器标签、左上角站名、footer、分享卡片全部一起变，不用再去别的地方找。

**唯一要额外看一眼的地方**：首页大标题那几句宣传语单独放在根目录的 `index.md` 里（`hero:` 下面的 `name` / `text` / `tagline`）。那是首页的文案，跟站名不完全是一回事，改站名的时候顺手看一下要不要一起改。

---

## 二、本地预览（在自己电脑上先看看效果）

只需要装一次 [Node.js](https://nodejs.org/)（选 LTS 版本），然后在仓库文件夹里打开终端：

```bash
npm install      # 第一次跑，装依赖，几分钟
npm run docs:dev # 启动本地预览
```

终端会打印一个地址，一般是 `http://localhost:5173`，浏览器打开就能看。改任何 md 文件保存后网页会自动刷新，不用重启。

想看"正式构建出来是什么样"：

```bash
npm run docs:build   # 生成静态网页，输出到 .vitepress/dist
npm run docs:preview # 本地起个服务预览 dist 里的成品
```

## 三、部署到 Vercel 并绑自定义域名（推荐方案，三步）

**第一步 · 连仓库。** 用 GitHub 账号登录 [vercel.com](https://vercel.com)，点 Add New → Project，选中 `fde-arsenal` 这个仓库，点 Import。

**第二步 · 填构建配置。** 在 Configure Project 页面里填三项，其他保持默认：

| 项目 | 填什么 |
| --- | --- |
| Framework Preset | VitePress（列表里没有就选 Other） |
| Build Command | `npm run docs:build` |
| Output Directory | `.vitepress/dist` |

点 Deploy，等一两分钟。第一次部署完会给你一个 `xxx.vercel.app` 的临时地址。

**第三步 · 绑自己的域名。** 进项目的 Settings → Domains，输入你自己的域名（比如 `fde.你的域名.com`），Vercel 会告诉你要在域名服务商那边加一条什么解析记录（一般是一条 CNAME）。去阿里云/腾讯云/Cloudflare 的域名控制台照着加上，等几分钟生效。证书（https）Vercel 自动办，不用管。

弄完之后，以后每次往 GitHub 的 main 分支推送内容，Vercel 会自动重新构建、自动上线，不需要再做任何操作。

---

## 四、为什么推荐 Vercel + 自定义域名，而不是用默认的 vercel.app

这是这套方案里唯一真正要紧的决定。

**`*.vercel.app` 这个域名在中国大陆访问不稳定。** 它是被整体处理的一个域，不是你这个站单独的问题——换个项目名也没用。如果读者主要在国内，用默认域名等于白部署。

**换成自己的域名就绕开了这件事。** 用户访问的是你自己的域名，走的是 Vercel 的 CDN 边缘节点，国内可访问性比 `vercel.app` 好得多。这是目前"不备案、不买国内服务器"的前提下，性价比最高的做法。

需要知道的两个前提：

- 你得有一个自己的域名（一年几十块钱）。
- 不做国内备案的话，速度是"能开、但不算飞快"。如果哪天读者量大了、对速度要求高了，正经解法是把站放到国内云厂商 + 域名备案，那是另一件事，现在不用考虑。

## 五、GitHub Pages 方案的取舍

仓库里已经放了一份现成的 GitHub Pages 自动部署配置：`.github/workflows/deploy.yml`。要用它，去仓库 Settings → Pages → Source 选成 "GitHub Actions" 就行，不用写代码。

两种方案的差别：

| | Vercel + 自定义域名 | GitHub Pages |
| --- | --- | --- |
| 国内访问 | 可用，速度中等 | **很不稳定，基本指望不上** |
| 自定义域名 | 支持 | 支持 |
| https 证书 | 自动 | 自动 |
| 配置难度 | 网页上点几下 | 改一个设置项 |
| 费用 | 个人用免费 | 免费 |

**结论**：主力用 Vercel + 自己的域名。GitHub Pages 当备份，或者给能翻墙的读者多留一个入口。两个同时开着也没问题，各自构建各自的，内容一样，不会打架。

## 六、这次一共加了哪些文件

全部是新增，没有修改或移动任何一篇内容 markdown。

```
.vitepress/config.mts       主配置：站名、导航、搜索、页脚
.vitepress/sidebar.mts      侧边栏自动生成脚本（见下）
.vitepress/部署说明.md      就是你正在看的这份
index.md                    网站首页（README.md 原样保留，给 GitHub 页面用）
package.json                声明依赖和三条命令
.gitignore                  让构建产物和依赖不进 git
.github/workflows/deploy.yml  GitHub Pages 自动部署（用 Vercel 的话可以不管）
```

**侧边栏是自动生成的。** `.vitepress/sidebar.mts` 会在每次构建时扫描 `01-原典` 到 `07-情报站`、`book`、`course` 这些文件夹，把里面的 md 文件自动排进侧边栏，标题取文件里的第一个大标题。所以**以后新增文章不用改任何配置**，写完 md 文件推上去就出现在网站上了。

只有两种情况才需要动 `sidebar.mts`：新增了一个顶级文件夹（要在 `SECTIONS` 里加一行），或者想调整某个文件夹里的排序（改 `priority`）。
